# A1-1 평가 순서

프로젝트를 처음 보는 제출자와 평가자가 그대로 따라갈 수 있는 순서입니다.

## 1. GitHub에서 먼저 볼 것

1. 이 폴더의 `README.md`에서 목적과 기능을 확인합니다.
2. `SUBMISSION.md`의 요구사항 대조표를 확인합니다.
3. `prompt_manager.py`에서 `DEFAULT_PROMPTS`, 기능별 함수, `main()`을 확인합니다.
4. `tests/test_prompt_manager.py`에서 검증 범위를 확인합니다.

발표 첫 문장은 다음과 같이 설명합니다.

> A1-1은 Python과 Git 기초를 증명하는 콘솔 프롬프트 관리 프로그램입니다. 이전 미션 3개와
> MateAI 개발 프롬프트 5개를 기본 데이터로 재사용했지만, ML 성능을 검증한 과제는 아닙니다.

## 2. 실행 준비

```bash
git clone https://github.com/kimble125/mateai-web.git
cd mateai-web/tasks/A1-1-prompt-manager
python3 prompt_manager.py
```

외부 패키지는 필요하지 않습니다. Python 3.10 이상이면 됩니다.

## 3. 약 3분 기능 시연

다음 입력 순서로 핵심 기능을 한 번에 보여 줍니다.

1. `2` — 기본 프롬프트 8개 확인
2. `1` — 새 프롬프트 추가
   - 제목: `평가용 프롬프트`
   - 내용: `장기기억 실험 결과를 사실과 해석으로 구분해 요약해줘`
   - 카테고리: `1`(텍스트 생성)
3. `4` → 검색어 `평가용` — 제목·내용 검색 확인
4. `5` → 번호 `9` — 상세 내용과 조회수 증가 확인
5. `6` → 번호 `9` — 즐겨찾기 추가
6. `7` — 즐겨찾기 목록 확인
7. `13` — 조회수 기준 Top 목록 확인
8. `0` — 종료

번호 `9`는 기본 데이터 8개 뒤에 처음 추가했을 때의 번호입니다. 다른 데이터를 먼저 추가했다면
목록에 표시된 실제 번호를 사용합니다.

## 4. 자동 테스트

```bash
python3 -m unittest discover -s tests -v
```

4개 테스트가 모두 `ok`, 마지막 줄이 `OK`인지 확인합니다. 테스트는 기본 데이터 구조,
추가→검색→상세→즐겨찾기 흐름, 명시적 저장·불러오기·내보내기, 잘못된 메뉴 입력을 검사합니다.

## 6. 질문을 받으면 짧게 답할 것

- **왜 저장소가 두 개인가?** 통합 저장소는 A1-1~A1-3의 연결을 보여 주고, 원본 저장소는 A1-1의 독립적인 Git 이력을 보존합니다.
- **저장 기능이 종료 시 초기화 요구와 충돌하지 않나?** 자동 저장하지 않고 메뉴 8·9를 직접 고를 때만 파일을 사용하므로 기본 동작은 초기화입니다.
- **MateAI와 무엇이 연결되나?** MateAI에서 실제 쓴 프롬프트 5개를 관리 대상으로 재사용했습니다. 다만 이 과제를 ML 연구 성과로 과장하지 않습니다.
- **테스트를 왜 넣었나?** 입력 중심 콘솔 프로그램도 기능 추가 때 기존 흐름이 깨질 수 있어 핵심 동작을 자동 점검했습니다.
