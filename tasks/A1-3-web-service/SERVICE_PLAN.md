# MateAI 서비스 기획서 (A1-3)

## 1. 서비스 개요
- **서비스명:** MateAI
- **목적:** 여행 중 친근한 대화와 구체적인 장소·일정 확인을 한 화면에서 오가게 하고, AI가 만든 정보의 확인 수준을 구분해 보여 준다.
- **타겟:** 한국을 처음 방문하는 영어권 개별 여행자. 화면·대화·리포트 모두 영어이며 지명은 한국어 원문을 함께 보존한다
- **핵심 가치:** 장소 검색 결과와 대조된 정보 / AI 추정 / 도구 실패를 구분해 사용자가 스스로 판단할 수 있게 한다.
- **문제 가설 (미검증):** 대화와 정보 확인을 오가며 맥락을 잃고, 생성된 정보가 어디까지 사실인지 알기 어렵다. 사용자 조사로 입증한 것은 아니다.

## 2. 페이지 구성 (2026-09-11 개편, 상단 메뉴로 이동)

| 페이지 | 파일 | 내용 |
|---|---|---|
| Home | `index.html` | 서비스 소개와 대화 예시, 두 기능으로 가는 진입점 |
| Chat | `chat.html` | 현지 친구와 대화. 채팅 안에서 여행 리포트 생성, 지연 상황 데모 |

## 3. AI 기능 설계

### 기능 A — 여행 리포트 (`POST /api/travel`)
- **입력:** `date` 실제 날짜 `YYYY-MM-DD`, `cities` 정수 1~2
- **처리:** LLM 지역 추천(JSON) → 지도 API 맛집 검색 → LLM 리포트 작성 → 가게 이름 근거 검사
- **출력:** 6개 섹션 마크다운 리포트(추천 지역/이유/날씨/행사/맛집/1일 일정), `places`, `grounding`, `errors`, `status`
- **사용자 가치:** 날짜만 넣으면 일정 초안을 받고, 어떤 가게가 실제 검색으로 확인됐는지 바로 본다.

### 기능 B — 대화 (`POST /api/chat`)
- **입력:** `utterance` 문자열(최대 500자), 최근 대화 `history`(최대 12턴), 여행 리포트 `context`(최대 3000자), 지연 여부 등 상태 필드
- **페르소나:** 입력자는 한국 여행 온 외국인, 응답자는 한국인 현지 친구 가이드. 이름·서사는 두지 않는다
- **출력:** 응답, 모드(동행/안내), 생성기와 LLM 호출 수
- **특징:** 안내(guide) 모드는 LLM 없이 결정론 템플릿으로 답해 틀린 교통 정보를 지어내지 않는다.

## 4. 실패 처리 기준

| 실패 | 서버 | 화면 |
|---|---|---|
| 빈 입력·잘못된 날짜·잘못된 지역 수 | `400` + `EMPTY_INPUT`/`BAD_DATE`/`BAD_CITIES` | 입력칸 아래 안내 |
| JSON 형식 오류 | `400 BAD_JSON` | "요청 형식이 잘못되었습니다" |
| AI 키 없음 | `400 NO_LLM_KEY` | 관리자 문의 안내 (AI 성공으로 표시하지 않음) |
| 추천 JSON 파싱 실패 | 1회만 재시도, 그래도 실패 시 `RECOMMEND_FAILED` | 다시 시도 안내 |
| 장소 검색 실패/0건 | 부분 결과, `status: partial` | "데이터 없음" + 오류 요약 |
| 리포트 LLM 실패 | 6개 섹션 폴백 리포트 | 폴백임을 ⚠️로 명시 |
| 예상 못한 예외 | `500`, 원시 오류 본문 비노출 | "잠시 후 다시 시도" |
| 호출 과다 | `429 RATE_LIMITED` / `BUDGET_EXHAUSTED` | 잠시 후 다시 시도 안내 |
| 60초 초과 | — | 타임아웃 안내, 버튼 재활성화 |

## 5. 호출·비용 고려
- 여행 1회 요청: LLM 최대 3회(추천 최대 2 + 리포트 1), 장소 검색 최대 2회(도시별 1)
- 대화: 동행 모드 LLM 최대 1회, 안내 모드 0회
- 요청 중 버튼 비활성화로 중복 제출을 막는다.
- 키는 서버 환경 변수에만 둔다. 브라우저 코드와 요청은 누구나 볼 수 있기 때문이다.
