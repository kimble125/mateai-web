# A1-2 제출 체크

최종 점검일: 2026-09-03

## 결론

필수 기능과 선택 보너스 2개를 구현했습니다. 실제 API 실행으로 만든 JSON·Markdown 예시도
[`results/`](results/)에서 바로 확인할 수 있습니다. 실제 API 키는 포함하지 않습니다.

## 요구사항 대조표

| 요구사항 | 상태 | 근거 |
|---|:---:|---|
| `argparse`, 필수 날짜, 잘못된 날짜 종료 | ✅ | `build_parser()`, `parse_date()`; `-date`와 `--date` 모두 지원 |
| LLM API | ✅ | Gemini 주 제공자, OpenAI 폴백 |
| 국내 장소 API | ✅ | Kakao 주 제공자, Naver 폴백 |
| 1차 추천 JSON | ✅ | 도시·날씨·행사·이유 타입 검증 후 다음 단계 입력으로 사용 |
| 지역별 맛집 권장 5곳 | ✅ | 기본 `--spots 5`; 이름·주소·분류·URL·좌표 저장 |
| 검색 0건·장소 API 실패 시 계속 | ✅ | 빈 목록과 오류를 기록하고 리포트 생성 계속 |
| 최종 Markdown 6개 섹션 | ✅ | 추천 지역·이유·날씨·행사·맛집·1일 일정 |
| JSON 파싱 실패 재시도 1회 | ✅ | `step_recommend()`의 2회 한정 반복 |
| 오류 목록 | ✅ | JSON과 Markdown 양쪽에 기록 |
| API 키 보호 | ✅ | `.env` 사용, `.gitignore` 제외, `.env.example`만 공개 |
| `results/` JSON·Markdown 저장 | ✅ | `save_results()` 및 검증된 공개 예시 1쌍 |
| 보너스: 2~3개 지역 | ✅ | `--cities 2` 또는 `3` |
| 보너스: 날짜별 캐시 | ✅ | 같은 날짜의 raw JSON 재사용; `--no-cache`로 무시 가능 |

## 정확한 한계

- 날씨·행사는 실시간 데이터가 아니라 LLM의 일반적 추정이므로 리포트에 `(추정)`으로 표시합니다.
- 폴백 제공자는 가용성 확보를 위한 추가 기능입니다. 어느 제공자가 응답했는지 결과에 남깁니다.
- 공개된 예시는 2026-08-27에 2026-03-15 여행일을 입력해 실행한 결과입니다. 최신 여행 정보가 아닙니다.
