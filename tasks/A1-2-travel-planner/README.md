# 국내 여행지 추천 리포트 생성기

여행 날짜를 주면 **LLM이 지역을 추천하고, 지도 API가 맛집을 찾고, 다시 LLM이
여행 리포트를 씁니다.** 그리고 **리포트에 적힌 가게가 실제로 검색된 곳인지 검사합니다.**

```
$ python3 travel_planner.py --date 2026-03-15 --cities 2

2026-03-15 국내 여행 리포트
LLM gemini → openai · 장소 kakao → naver

[1/3] 1차 추천 생성 중 (LLM) …
[1/3] 추천 지역: 경주, 제주 (gemini)
[2/3] 맛집 검색 중 (지도 API) …
[2/3] 경주: 5곳 (kakao)
[2/3] 제주: 5곳 (kakao)
[3/3] 최종 리포트 생성 중 (LLM) …
[3/3] 리포트 생성 완료 (gemini)
[가드] 가게 이름 10건 전부 검색 결과와 일치

완료!
  리포트   results/2026-03-15_travel_plan.md
  원본     results/2026-03-15_raw.json
```

---

## 실행 방법

```bash
git clone https://github.com/kimble125/travel-planner.git
cd travel-planner

cp .env.example .env        # 키 서식 복사
open -e .env                # 값 채우기 (아래 참조)

python3 travel_planner.py --date 2026-03-15
```

**요구 사항**: Python 3.10 이상. 외부 패키지 없이 **표준 라이브러리만** 씁니다.

### 옵션

| 옵션 | 설명 |
|---|---|
| `--date YYYY-MM-DD` | **필수.** 여행 날짜. 형식이 틀리면 사용법을 출력하고 종료합니다 |
| `--cities N` | 추천받을 지역 수 (1~3, 기본 1) — **보너스 1** |
| `--spots N` | 지역당 맛집 개수 (기본 5) |
| `--no-cache` | 저장된 결과가 있어도 API를 다시 호출 — **보너스 2** |

## API 키 설정

키는 **`.env` 파일에만** 넣습니다. 코드·README·결과물 어디에도 적지 않습니다.
`.gitignore` 가 `.env` 를 막고 있습니다.

| 키 | 용도 | 발급 |
|---|---|---|
| `GEMINI_API_KEY` | LLM (주) | https://aistudio.google.com/apikey |
| `OPENAI_API_KEY` | LLM (보조) | https://platform.openai.com/api-keys |
| `KAKAO_REST_API_KEY` | 장소 검색 (주) | https://developers.kakao.com → 앱 → **앱 키 → REST API 키** |
| `NAVER_CLIENT_ID` / `_SECRET` | 장소 검색 (보조) | https://developers.naver.com/apps/#/register (사용 API: **검색**) |

> **Kakao 주의**: 키를 발급해도 앱에서 **카카오맵 서비스를 활성화**하지 않으면
> `403 disabled OPEN_MAP_AND_LOCAL service` 가 납니다.
> 콘솔 좌측 **카카오맵 → 활성화 설정 ON**.

키가 하나도 없으면 프로그램이 **즉시 종료하고 설정 방법을 안내**합니다.

### 키가 유출되었다면

1. 발급처에서 **즉시 폐기 후 재발급** — 이것이 1순위입니다
2. 커밋에 들어갔다면 이력까지 정리해야 합니다. 재발급이 먼저입니다

## 결과물

`results/` 폴더에 두 개가 생깁니다. (이 폴더는 `.gitignore` 대상입니다)

| 파일 | 내용 |
|---|---|
| `{날짜}_raw.json` | 1차 추천 JSON · 지역별 맛집 검색 결과 · **근거 검사 결과** · `errors` 배열 |
| `{날짜}_travel_plan.md` | 최종 여행 리포트 |

리포트 구성: `추천 지역` · `추천 이유` · `날씨 요약` · `행사·축제` · `맛집 추천` ·
`1일 일정 제안` · **`근거 출처`** · **`오류 요약(errors)`**

## 설계에서 다르게 한 것

### 1. 근거 가드 — 리포트가 지어낸 가게를 잡습니다

과제는 *"실제 날씨/행사 데이터의 정확도를 평가하는 미션이 아니다"* 라고 명시합니다.
**그런데 맛집은 다릅니다.** 지도 API가 실제 데이터를 주는데도, 최종 리포트를 쓰는
LLM이 없는 가게를 만들어 낼 수 있습니다. 그 문장은 **검증 가능**하므로 검사합니다.

```
[가드] 근거 없는 가게 이름 1건 표시: 경주전통한우마을
```

리포트에는 이렇게 남습니다.

```markdown
*   **경주전통한우마을** — 경북 경주시 어딘가 (한식)  <!-- ⚠️ 근거 없음: ... -->
```

프롬프트에도 *"목록에 있는 가게만"* 이라고 적지만, **프롬프트는 요청이고 가드는 검사**입니다.
둘은 대체 관계가 아닙니다.

이 메커니즘은 제가 만든 캐릭터챗 엔진 **MateAI**의 `grounding.py` 에서 가져왔습니다.
거기서는 시각·열차번호를 검사했고, 여기서는 가게 이름을 검사합니다.
**메커니즘은 같고 검사 대상만 도메인에 맞게 바꿨습니다.**

### 2. 검사할 수 없는 것은 검사한 척하지 않습니다

날씨와 행사는 LLM 추정입니다. 대조할 근거가 없습니다.
그래서 **검사하지 않는 대신 리포트에 `(추정)` 을 붙입니다.**

### 3. 제거가 아니라 표시입니다

MateAI는 근거 없는 문장을 **제거**했습니다. 여기서는 **표시만** 합니다.
리포트는 사람이 읽고 판단하는 문서이고, 지워 버리면 무엇이 문제였는지
독자가 알 수 없기 때문입니다.

### 4. 한 단계가 실패해도 리포트는 나옵니다

| 실패 | 대응 |
|---|---|
| API 키 없음 | 즉시 종료 + 설정 방법 안내 |
| 지도 API 실패(인증/쿼터/네트워크) | 맛집 `데이터 없음` 으로 **리포트 생성은 계속** |
| 검색 결과 0건 | 실패가 아닙니다. `데이터 없음` 으로 넘깁니다 |
| LLM JSON 파싱 실패 | **재시도 1회**, 두 번째는 요구를 최소로 줄인 프롬프트. 그래도 실패하면 종료 |
| 리포트 LLM 실패 | 자료를 그대로 정리한 **최소 리포트**를 만듭니다 |

모든 실패는 `errors` 배열에 모여 **JSON과 리포트 양쪽에 기록**됩니다.

### 5. 제공자 폴백

주 제공자가 죽으면 보조로 자동 전환합니다 — `LLM: Gemini → OpenAI`, `장소: Kakao → Naver`.

> **과제 요구사항 해석에 관하여**: 과제는 LLM과 지도 API를 각각 *"택1"* 로 구현하라고 합니다.
> 이 구현은 두 제공자를 쓰지만 **양쪽 모두 과제가 허용한 목록 안**입니다
> (LLM: OpenAI 계열 / Gemini 계열, 장소: Kakao Local / Naver Local).
> 전환은 **호출 가능성 문제**(인증·쿼터·네트워크·5xx)일 때만 하고,
> **빈 결과(0건)는 실패로 치지 않습니다** — 과제 요구대로 `데이터 없음` 으로 넘깁니다.
> 어느 제공자가 답했는지는 항상 `errors` 와 리포트에 기록됩니다.

### 6. 캐시는 원본 JSON만 (보너스 2)

같은 `--date` 로 다시 실행하면 저장된 원본 JSON을 읽어 **API 호출을 건너뜁니다.**
다만 **리포트는 매번 다시 만듭니다** — 비싼 것은 API 호출이지 리포트 조립이 아니고,
프롬프트를 고치면 리포트는 바뀌어야 하기 때문입니다.
