# 나만의 프롬프트 관리

터미널에서 메뉴 번호를 골라 프롬프트를 보관하고 찾아 쓰는 콘솔 프로그램입니다.
표준 라이브러리만 사용합니다 — 설치할 것이 없습니다.

```
=== 나만의 프롬프트 관리 ===
1. 프롬프트 추가          8. 파일로 저장
2. 프롬프트 목록          9. 파일에서 불러오기
3. 카테고리별 조회       10. Markdown으로 내보내기
4. 프롬프트 검색         11. 프롬프트 수정
5. 프롬프트 상세 보기    12. 프롬프트 삭제
6. 즐겨찾기 관리         13. 많이 쓴 프롬프트 (Top)
7. 즐겨찾기 목록          0. 종료
선택:
```

---

## 실행 방법

```bash
git clone https://github.com/<사용자명>/prompt-manager.git
cd prompt-manager
python3 prompt_manager.py
```

**요구 사항**: Python 3.10 이상 (개발·확인 환경 3.14.5)
외부 패키지는 쓰지 않습니다.

---

## 기능

### 기본

| 메뉴 | 하는 일 |
|---|---|
| 1. 프롬프트 추가 | 제목·내용·카테고리를 받아 등록합니다. 빈 값은 다시 묻습니다 |
| 2. 프롬프트 목록 | 번호·카테고리·제목·즐겨찾기(⭐)를 한 줄로 보여 줍니다 |
| 3. 카테고리별 조회 | 카테고리를 골라 해당 프롬프트만 봅니다 |
| 4. 프롬프트 검색 | **제목과 내용을 함께** 찾습니다. 대소문자 구분 없음 |
| 5. 프롬프트 상세 보기 | 전체 내용을 봅니다. 볼 때마다 사용 횟수가 올라갑니다 |
| 6. 즐겨찾기 관리 | 번호를 넣으면 추가/해제가 토글됩니다 |
| 7. 즐겨찾기 목록 | ⭐ 표시한 것만 모아 봅니다 |

기본 상태에서는 **종료하면 초기화**됩니다. 남기고 싶을 때만 8번으로 저장합니다.

### 보너스

| 메뉴 | 하는 일 |
|---|---|
| 8. 파일로 저장 | `prompts.json` 으로 저장합니다 |
| 9. 파일에서 불러오기 | 저장해 둔 파일을 되살립니다 |
| 10. Markdown으로 내보내기 | `exports/` 에 **카테고리별 `.md` 파일**을 만듭니다 |
| 11. 프롬프트 수정 | 제목·내용·카테고리를 고칩니다. Enter를 치면 그대로 둡니다 |
| 12. 프롬프트 삭제 | 되돌릴 수 없으므로 한 번 더 확인합니다 |
| 13. 많이 쓴 프롬프트 | 사용 횟수 순으로 정렬해 보여 줍니다 |

## 등록된 카테고리

`텍스트 생성` · `이미지 생성` · `영상 생성` · `페르소나` · `자동화` · `기타`

추가할 때 **직접 입력**을 고르면 새 카테고리를 만들 수 있고,
카테고리별 조회 화면에도 자동으로 나타납니다.

## 기본 데이터에 관하여

기본 프롬프트 8개는 예시용 문구가 아니라 **제가 이전 미션과 프로젝트에서 실제로 쓴 것들**입니다.
그래서 각 프롬프트의 내용에 **"왜 이렇게 썼는지"**, 그리고 지금 돌아보니 무엇이었는지를
함께 적어 두었습니다.

### 코디세이 이전 미션에서 (3개)

| 프롬프트 | 미션 | 돌아보니 |
|---|---|---|
| 매일 투자 일지 생성 — 항해사 '킴블' | B1-1 프롬프트 엔지니어링 | *"제공 안 된 수치는 지어내지 말고 '확인 필요'로 표기"* — 이게 곧 cite-or-refuse였습니다 |
| 주간 블로그 초고 — 캐릭터 대사는 자리만 | B1-1 | **사실은 AI가, 캐릭터는 사람이.** 레이어를 나눈 첫 시도였습니다 |
| 영상 생성 — 원화 보존과 금지 목록 | B1-2 멀티모달 | 금지 목록이 프롬프트의 절반입니다. 생성 모델에선 "하지 마라"가 더 강하게 작동합니다 |

### MateAI(캐릭터챗 엔진) 개발에서 (5개)

| 프롬프트 | 무엇에 대한 기록인가 |
|---|---|
| 압축 시스템 프롬프트 (202→69토큰) | 학습 연산의 82%가 매번 같은 지시문을 다시 읽는 데 쓰이고 있었습니다. 규칙을 버리지 않고 문장만 줄였습니다 |
| 근거 가드 — cite-or-refuse | 사실 주장만 좁게 뽑아 근거와 대조하고, 위반한 **문장만** 제거합니다 |
| 선호 데이터 6단계 정제 기준 | 유저의 '다시 생성' 클릭을 학습 신호로 쓸 때 원시 쌍을 그대로 넣지 않는 이유 |
| 컴패니언 프롬프트 조립 규칙 | 근거를 주지 않으면 모델은 사실을 말할 방법 자체가 없습니다 |
| DPO 실험 arm 정의 | 하이퍼파라미터가 arm마다 다른 세기로 작동하지 않는지 먼저 확인할 것 |

> **한 가지 발견**: B1-1에서 쓴 안전장치(*"지어내지 말고 확인 필요로"*, *"캐릭터 대사는 자리만"*)가
> 나중에 MateAI의 근거 가드·레이어 분리와 같은 발상이었습니다.
> 이 보관함을 만들면서 알았습니다 — 프롬프트를 모아 두면 **내 설계 습관이 보입니다.**

> `페르소나` 카테고리는 앞으로 **투닝플러스로 제작할 캐릭터 카드**가 들어갈 자리입니다.
> 지금은 프롬프트의 *구조*만 등록해 두었습니다.

## 설계 메모

### 왜 함수를 이렇게 나눴나

```
입력 도우미      ask() · ask_category() · pick_index()
출력 도우미      format_row() · print_rows() · line()
기능             add_prompt() · show_list() · show_by_category() · search_prompt()
                 show_detail() · toggle_favorite() · show_favorites()
보너스           save_to_file() · load_from_file() · export_markdown()
                 edit_prompt() · delete_prompt() · show_top()
진입점           main()
```

목록을 찍는 화면이 **네 개**(전체 목록·카테고리별·검색 결과·즐겨찾기)라
`print_rows()` 하나로 묶었습니다. 한 곳만 고치면 네 화면이 같이 바뀝니다.

### 13번 메뉴가 답하는 질문

**"내가 실제로 무엇을 쓰는가."**

즐겨찾기는 내가 중요하다고 *선언한* 것이고, 사용 횟수는 실제 *행동*입니다.
둘은 자주 어긋납니다. 그래서 Top 목록에는 **"즐겨찾기는 아닌데 많이 씀"** 표시를 붙였습니다.

이건 MateAI에서 유저 행동을 학습 신호로 다룰 때와 같은 발상입니다.
'좋아요'는 선언이고 '재생성하지 않고 넘어감'은 행동입니다 — 다른 신호로 취급해야 합니다.
